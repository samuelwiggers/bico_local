# Relatório de andamento — 03/11/2026

O projeto BicoLocal está sendo desenvolvido na disciplina Desenvolvimento em Plataformas Móveis, do curso de Sistemas de Informação da Unidavi. A proposta busca organizar a divulgação de trabalhos temporários, diárias e pequenos serviços no Alto Vale do Itajaí, aproximando trabalhadores autônomos, estudantes, moradores e pequenos estabelecimentos. O recorte desta primeira etapa é um protótipo móvel que permita demonstrar os principais fluxos sem depender de backend ou de contas reais.

Até a data deste relatório, foi preparado o ambiente do projeto Flutter diretamente no diretório definido para o trabalho e estruturada uma aplicação Android com suporte a Material 3. Foram elaborados documentos iniciais de proposta, requisitos, planejamento, arquitetura e roteiro para levantamento comunitário. Também foram implementados o modelo de oportunidade com validações básicas, um conjunto de dados fictícios, busca por texto, filtro por categoria, listagem em cartões, consulta de detalhes, registro de interesse único durante a sessão, cadastro em memória e perfil demonstrativo. O estado dos registros é mantido enquanto a aplicação permanece aberta; não há persistência após reinicialização.

O trabalho está organizado em telas, modelo, dados, serviço de estado e componente reutilizável para cartões. Essa organização procura manter responsabilidades compreensíveis ao escopo acadêmico e permite explicar as decisões sem adotar uma arquitetura excessivamente abstrata. Os testes automatizados contemplam regras do modelo, busca e filtro, cadastro, duplicidade de interesse e uma verificação de navegação.

Durante a configuração, a execução do Flutter no SDK original encontrou restrição de escrita em arquivos de cache fora da pasta do projeto. Uma cópia temporária do SDK em `/tmp` permitiu gerar o scaffold. A resolução inicial de dependências também não teve acesso à rede; posteriormente, `flutter pub get --offline` concluiu usando o cache local e uma área temporária para o cache de pacotes. A criação de repositório Git no diretório não foi possível porque existe ali uma pasta `.git` sem permissão de escrita. O ADB também não iniciou seu servidor neste ambiente isolado, portanto não há captura confirmada de um dispositivo Android nesta etapa.

Neste momento, os principais fluxos foram implementados no código. A análise estática terminou sem apontamentos; os testes foram criados, mas o runner não pôde iniciá-los porque o sandbox bloqueia sockets locais. A pesquisa com trabalhadores e contratantes ainda não foi realizada; por isso, necessidades descritas no projeto são hipóteses e os registros exibidos são fictícios. Como próximos passos, recomenda-se executar a aplicação em emulador ou aparelho, revisar as telas com a turma, realizar levantamento comunitário com consentimento, incorporar aprendizados ao protótipo e preparar apresentação e vídeo para a entrega final de 01/12/2026.

Conclui-se que a primeira versão do BicoLocal já oferece uma base navegável para avaliar o problema e discutir os fluxos propostos. A validação com usuários, persistência e evidências em dispositivo permanecem necessárias antes de tratar o protótipo como solução pronta para uso real.
